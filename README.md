# 포켓 더비 (GitHub Pages 버전)

디스코드 커뮤니티 이벤트용 8인 실시간 레이스 미니게임입니다. 배팅, 코인 기능은 없습니다.
참가자는 1~8번 포켓몬 중 한 마리를 선점하고, 관리자가 레이스를 시작하면 1등 포켓몬을 선점한 사람이 우승자가 됩니다.

GitHub Pages는 정적 파일만 올릴 수 있어서 Node 서버를 실행할 수 없습니다.
그래서 실시간 동기화(닉네임, 선점, 레이스 진행)는 **Firebase Realtime Database**(무료 Spark 요금제로 충분)가 담당합니다.

## 파일 구성

```
index.html            화면 전체 (로비, 선점 패널, 캔버스 트랙, 관리자 패널, 결과 팝업)
config.js             Firebase 설정값 + 관리자 이메일 (직접 입력)
database.rules.json   Firebase 데이터베이스 보안 규칙 (콘솔에 붙여넣기)
runners/              runner1.png ~ runner8.png 를 넣으면 해당 레인에 이미지로 표시
.nojekyll             GitHub Pages가 파일을 가공하지 않도록 하는 빈 파일
```

---

## 1단계. Firebase 프로젝트 만들기 (약 10분)

1. https://console.firebase.google.com 접속 -> **프로젝트 추가** -> 이름 입력 (Google 애널리틱스는 꺼도 됨)
2. 왼쪽 메뉴 **빌드 > Realtime Database** -> **데이터베이스 만들기**
   - 위치: `asia-southeast1 (싱가포르)` 권장
   - 보안 규칙: **잠금 모드**로 시작 (아래 3단계에서 규칙을 교체합니다)
3. 왼쪽 메뉴 **빌드 > Authentication** -> **시작하기** -> **로그인 방법** 탭에서 두 가지를 사용 설정
   - **익명** (참가자용)
   - **이메일/비밀번호** (관리자용)
4. Authentication -> **사용자** 탭 -> **사용자 추가** -> 관리자로 쓸 이메일과 비밀번호 등록
   - 예: `myevent.admin@gmail.com` (실제로 메일을 받을 필요는 없지만 본인만 아는 주소를 쓰세요)
   - 반드시 이 단계를 사이트 공개 전에 해 두세요. 같은 이메일로 다른 사람이 먼저 가입하는 것을 막습니다.

## 2단계. config.js 채우기

1. Firebase 콘솔 왼쪽 위 톱니바퀴 -> **프로젝트 설정** -> 아래쪽 **내 앱** -> 웹 아이콘(`</>`) 클릭 -> 앱 이름 입력 후 등록 (Hosting 체크는 하지 않음)
2. 화면에 나오는 `firebaseConfig` 값을 `config.js` 에 그대로 붙여넣기
   - `databaseURL` 항목이 꼭 있어야 합니다. 없으면 Realtime Database 화면 상단의 `https://....firebasedatabase.app` 주소를 직접 넣으세요.
3. `ADMIN_EMAIL` 에 1단계에서 만든 관리자 이메일 입력

## 3단계. 보안 규칙 게시

1. `database.rules.json` 파일을 열어 `admin@example.com` 을 **관리자 이메일로 바꿉니다** (1곳)
2. Firebase 콘솔 -> Realtime Database -> **규칙** 탭 -> 기존 내용을 지우고 파일 내용을 전부 붙여넣기 -> **게시**

이 규칙이 하는 일:
- 레이스 시작, 초기화, 이름 변경 같은 관리자 작업은 관리자 이메일 계정만 가능
- 한 사람당 말 1마리만 선점 가능, 이미 잡힌 말은 다른 사람이 덮어쓸 수 없음
- 레이스가 시작되면 선점 변경 불가
- 같은 닉네임 중복 사용 불가

## 4단계. GitHub에 올리고 Pages 켜기

1. GitHub에서 새 저장소 생성 (Public, 예: `poke-derby`)
2. 이 폴더의 파일을 **저장소 최상위**에 업로드 (`index.html` 이 저장소 루트에 바로 보여야 합니다)
   - 웹에서 올리기: 저장소 -> **Add file > Upload files** -> 파일과 `runners` 폴더를 드래그 -> Commit
   - `.nojekyll` 처럼 점으로 시작하는 파일이 드래그로 안 올라가면 **Add file > Create new file** 로 이름 `.nojekyll`, 내용은 비운 채 만들어도 됩니다
3. 저장소 **Settings > Pages** -> Source: **Deploy from a branch** -> Branch: `main` / `/ (root)` -> Save
4. 1~2분 후 `https://<깃허브아이디>.github.io/<저장소이름>/` 으로 접속

## 5단계. Firebase에 사이트 주소 허용 (필수)

Firebase 콘솔 -> Authentication -> **설정** 탭 -> **승인된 도메인** -> **도메인 추가** -> `<깃허브아이디>.github.io` 입력

이걸 빠뜨리면 익명 로그인이 막혀 사이트가 "연결 중"에서 멈춥니다.

## 이벤트 진행 방법

1. 디스코드에 사이트 주소 공유
2. 참가자: 닉네임 입력 -> 빈 말 클릭으로 선점 (다른 빈 말을 누르면 갈아타기, 선택 취소 가능)
3. 관리자: 화면의 [관리자] 또는 입장 창의 [관리자 로그인] -> 관리자 이메일/비밀번호 -> [레이스 시작]
   - 관리자는 참가자와 **다른 브라우저나 시크릿 창**을 쓰는 것을 권장합니다 (관리자 로그인 시 그 브라우저의 참가자 닉네임은 분리됩니다)
4. 3, 2, 1 카운트다운 후 모든 접속자 화면에서 같은 레이스가 재생됩니다
5. 결승 후 1등 포켓몬과 우승자 닉네임 대형 팝업 + 1~8등 순위표
6. 관리자: [새 라운드 준비] -> 다음 판

| 관리자 버튼 | 동작 |
|---|---|
| 레이스 시작 | 대기 단계에서만 가능. 8명이 다 안 찼으면 확인 후 시작 |
| 선택 초기화 | 모든 선점 해제 (라운드 번호 유지) |
| 새 라운드 준비 | 결과 화면을 닫고 선점 초기화, 다음 라운드로 |
| 진행 중 레이스 중단 | 카운트다운/레이스 취소, 대기로 복귀 (선점 유지, 이 판 기록 삭제) |
| 닉네임 전체 초기화 | 등록된 모든 닉네임과 선점 삭제 (이벤트가 끝난 뒤 정리용) |
| 레인별 해제 | 특정 참가자의 선점만 해제 (잠수 유저 정리) |
| 이름 변경 | 1~8번 포켓몬 표시 이름 변경 (모든 접속자에게 즉시 반영) |

## 커스텀 이미지

저장소의 `runners/` 폴더에 `runner1.png` ~ `runner8.png` 를 올리면 트랙, 선점 카드, 결과 팝업에 표시됩니다.
- 오른쪽을 바라보는 투명 배경 PNG 권장 (64~128px 정도, 자동 축소)
- 파일 이름은 소문자 그대로 (`Runner1.PNG` 는 인식 안 됨)
- 파일이 없으면 번호와 고유 색을 가진 기본 캐릭터가 대신 달립니다

## 공정성과 동기화 방식

- 레이스 시작 버튼을 누르는 순간, 관리자 브라우저가 암호학적 난수(`crypto.getRandomValues`)로 레이스 전체를 한 번에 계산해 저장합니다.
- 8마리 모두 같은 규칙, 같은 확률 분포를 씁니다 (특정 번호 보정 없음). 수천 판 시뮬레이션에서 번호별 우승 확률은 약 12.5%로 고르게 나옵니다.
- 모든 접속자는 Firebase 서버 시각을 기준으로 같은 장면을 재생하므로, 늦게 들어온 사람도 같은 위치를 봅니다. 관리자가 레이스 도중 창을 닫아도 레이스는 끝까지 진행됩니다.
- 결승선 통과 순서는 틱(0.1초) 내부의 정확한 통과 시점까지 계산해 판정합니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 상단에 "Firebase 설정이 필요합니다" | config.js 의 apiKey, databaseURL 입력 여부 |
| "익명 로그인 실패" | Authentication 에서 익명 사용 설정, 승인된 도메인에 github.io 추가 |
| "데이터 읽기 실패" | Realtime Database 생성 여부, 규칙 게시 여부 |
| 관리자 버튼을 눌러도 "권한이 없습니다" | config.js 와 database.rules.json 의 관리자 이메일이 로그인한 이메일과 같은지 |
| 수정한 파일이 반영 안 됨 | Pages 배포에 1~2분 소요, 브라우저 강력 새로고침(Ctrl+Shift+R) |
