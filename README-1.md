# 포켓 더비 (GitHub Pages + Firebase, 자동 진행 버전)

디스코드 커뮤니티 이벤트용 실시간 레이스 미니게임입니다. 배팅이나 코인 기능은 없습니다.

- 한국 시간 **0:30, 2:30, 4:30 … 22:30** (2시간 간격)에 경기가 자동으로 출발합니다
- 출발 **1분 전에 참가가 마감**됩니다 (예: 4:30 경기는 4:29 마감)
- 닉네임 입력 후 **참가하기**를 누르면 내 캐릭터가 생성되어 출전합니다 (1인 1캐릭터)
- 마감 때 참가자가 **6명 미만이면 그 회차는 취소**되고 다음 회차를 기다립니다
- 1등 캐릭터의 주인이 우승자이며, **우승 기록은 Firebase에 영구 저장**됩니다

## 파일 구성

```
index.html            화면 전체
config.js             Firebase 설정값, 관리자 이메일, 경기 일정
database.rules.json   Firebase 보안 규칙 (콘솔에 붙여넣기)
runners/              runner1.png ~ runner8.png 를 넣으면 해당 포켓몬 종류 캐릭터에 이미지로 표시
.nojekyll             GitHub Pages가 파일을 가공하지 않도록 하는 빈 파일
```

## 이전 버전에서 업데이트하는 경우 (이미 사이트를 운영 중이라면)

1. GitHub 저장소의 **index.html** 을 새 파일로 교체
2. GitHub 저장소의 **config.js** 를 열어(연필 아이콘) 맨 아래에 아래 내용을 추가 (firebaseConfig, ADMIN_EMAILS 는 그대로 둠)
   ```js
   export const SCHEDULE = {
     intervalMinutes: 120,
     offsetMinutes: 30,
     minPlayers: 6,
     maxPlayers: 20
   };
   ```
3. Firebase 콘솔 > Realtime Database > **규칙** 탭에 새 **database.rules.json** 내용을 붙여넣고 **게시**
   - 4번째 줄의 관리자 이메일을 본인 관리자 이메일로 바꾼 뒤 붙여넣으세요 (소문자)
4. 끝. 1~2분 뒤 사이트를 강력 새로고침(Ctrl+Shift+R)

이전 버전의 데이터(picks, room, history 등)는 더 이상 쓰이지 않습니다. 남아 있어도 문제는 없으며, 지우고 싶으면 Firebase 콘솔 데이터 탭에서 해당 항목을 삭제하면 됩니다.

## 처음부터 설치하는 경우

### 1. Firebase 프로젝트 만들기
1. https://console.firebase.google.com -> **프로젝트 만들기** (애널리틱스는 꺼도 됨)
2. **빌드 > Realtime Database > 데이터베이스 만들기** (위치: 싱가포르 asia-southeast1, 잠금 모드)
3. **빌드 > Authentication > 시작하기 > 로그인 방법** 에서 **익명**, **이메일/비밀번호** 사용 설정
4. Authentication > **사용자 > 사용자 추가** 로 관리자 계정 등록 (본인 Gmail 추천, 비밀번호는 새로 정함)

### 2. config.js 채우기
1. 톱니바퀴 > **프로젝트 설정** > **내 앱** > 웹(`</>`) 앱 등록 > `firebaseConfig` 값을 config.js 에 붙여넣기
   - `databaseURL` 이 꼭 있어야 합니다 (없으면 Realtime Database 화면 상단 주소를 직접 입력)
2. `ADMIN_EMAILS` 에 관리자 이메일 입력

### 3. 보안 규칙 게시
`database.rules.json` 4번째 줄의 `admin@example.com`, `admin2@example.com` 을 관리자 이메일로 바꾼 뒤,
Firebase 콘솔 > Realtime Database > **규칙** 탭에 전체를 붙여넣고 **게시**.
- 관리자가 1명이면 `|| auth.token.email == '...'` 부분을 지우고, 3명 이상이면 같은 형식으로 이어 붙입니다
- 이메일은 소문자로 쓰세요

### 4. GitHub Pages
1. 새 저장소(Public)에 이 폴더의 파일을 **최상위**에 업로드
2. **Settings > Pages** > Branch: `main` / `/ (root)` > Save

### 5. 사이트 주소 허용 (필수)
Firebase > Authentication > **설정 > 승인된 도메인** 에 `내아이디.github.io` 추가

## 경기 일정 바꾸기 (config.js 의 SCHEDULE)

| 항목 | 의미 | 예 |
|---|---|---|
| intervalMinutes | 경기 간격(분) | 120 = 2시간마다 |
| offsetMinutes | 자정 기준 첫 경기 시각(분) | 30 = 0:30, 2:30, 4:30 … / 90 = 1:30, 3:30, 5:30 … |
| minPlayers | 최소 인원 | 6 |
| maxPlayers | 한 경기 최대 인원 | 20 |

- 간격은 하루(1440분)를 나누어떨어지는 값으로 정하세요 (예: 60, 120, 180, 240)
- **시험해 보고 싶을 때:** 잠시 `intervalMinutes: 5, offsetMinutes: 0` 으로 올리면 5분마다 경기가 열립니다. 확인 후 원래 값으로 되돌리세요.

## 공정성과 기록이 보장되는 방식

서버가 없기 때문에, 결과를 특정 사람(관리자 포함)이 정하지 않도록 아래처럼 설계했습니다.

1. **참가 명단 고정:** 참가 기록에는 Firebase 서버 시각이 찍히고, 보안 규칙상 마감 시각 이후에는 추가, 수정, 취소가 불가능합니다.
2. **공용 난수:** 마감 30초 뒤에 공개되는 전 세계 공용 난수 서비스 [drand](https://drand.love) 의 값을 씨앗으로 씁니다. 마감 전에는 아무도 이 값을 알 수 없습니다.
3. **모두가 같은 계산:** 접속한 모든 브라우저가 "고정된 명단 + 공용 난수"로 똑같은 레이스를 각자 계산해 같은 장면을 봅니다. 모든 캐릭터는 같은 규칙과 같은 확률로 달립니다 (참가 순서와 무관하게 우승 확률이 같음을 시뮬레이션으로 확인).
4. **기록 저장:** 경기가 끝나면 접속자 중 한 명의 브라우저가 우승 기록(winners)과 전체 순위(results)를 저장합니다. 한 번 저장된 기록은 덮어쓸 수 없습니다.
5. **아무도 안 보고 있던 경기:** 경기 시각에 접속자가 없었더라도 참가 명단은 남아 있으므로, 그 후 누군가 사이트에 들어오면 자동으로 계산해 기록합니다 (최근 24시간분).
6. **기록 검증:** 화면의 우승 기록은 각 브라우저가 명단과 공용 난수로 다시 계산해 확인한 뒤 "검증됨"으로 표시합니다. 누군가 가짜 기록을 끼워 넣어도 화면에는 올바른 우승자가 나옵니다. 관리자 패널의 **우승 기록 검증 / 복구** 버튼은 최근 7일 기록을 다시 계산해 잘못된 기록을 바로잡습니다.

Firebase 콘솔의 데이터 탭에서 `winners` 항목을 보면 회차별(키 = 경기 시각) 우승자 기록을 직접 확인할 수 있습니다.

## 알아둘 점

- 1인 1캐릭터는 "브라우저 1개당 1명" 기준입니다. 한 사람이 다른 기기나 시크릿 창으로 다른 닉네임을 만들어 여러 번 참가하는 것까지는 막을 수 없습니다. 의심되는 참가자는 관리자가 마감 전에 [제외]로 뺄 수 있습니다.
- 인원 부족으로 취소된 회차의 참가자는 다음 회차에 **참가하기를 다시 눌러야** 합니다.
- 공용 난수 서버에 잠시 연결이 안 되면 "추첨 준비 중"으로 기다렸다가 자동 재시도합니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| "Firebase 설정이 필요합니다" | config.js 의 apiKey, databaseURL |
| "익명 로그인 실패" | 익명 로그인 사용 설정, 승인된 도메인에 github.io 추가 |
| "데이터 읽기 실패" | 새 database.rules.json 을 게시했는지 |
| 참가하기를 눌렀는데 "참가할 수 없습니다" | 새 규칙 게시 여부, 마감 시각이 지났는지 |
| 관리자 기능에서 "권한이 없습니다" | config.js 와 규칙의 관리자 이메일이 같은지(소문자) |
